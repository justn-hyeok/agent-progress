# 저장 형식 v1 초안과 신뢰 경계

## 단일 원본

Markdown 파일의 `ap-plan` fenced JSON 블록 하나가 원본이다. 위쪽 요약은
파생 표시이며 `ap show`/HUD는 항상 원본 블록을 읽는다. 요약만 편집해도
상태는 바뀌지 않는다. 알 수 없는 스키마 버전/필드와 불완전한 블록은 거부한다.

`Plan`에는 schema_version, 계획 UUID, project 식별 문자열, goal, created_at,
revision, tasks, history를 둔다. 파일 이름·날짜·현재 디렉터리로 세션이나
계획을 추론하지 않는다. project에는 사용자가 안정적인 식별자를 지정한다.
시각은 Unix 초이며 체크율이나 시간 예측에 사용하지 않는다.

작업은 UUID, 제목, 완료 조건 목록, 상태, 선행 UUID 목록, 요구 검증 종류,
근거 목록, 에이전트/세션 연결, 막힌 이유, 다음 행동을 가진다. 삭제 명령은
제공하지 않으며 취소 상태로 보존한다. 취소는 체크율 분자·분모에서 제외한다.
취소를 제외한 대상이 없으면 미정이다.

## 쓰기와 실패 처리

1. 부모 경로를 정규화하고 symlink 계획의 쓰기를 거부한다.
2. `<FILE>.ap-lock`의 OS advisory exclusive lock을 비차단 방식으로 획득한다.
3. 현재 파일을 읽어 검증하고 선택적 expected revision을 비교한다.
4. 메모리에서 변경, 이벤트 한 개 추가, 전체 불변식 검증을 수행한다.
5. 현재 파일의 바이트가 읽었던 내용과 같은지 다시 확인한다.
6. 같은 디렉터리의 임시 파일에 전체 상태와 이력을 쓰고 fsync한다.
7. 원자적으로 교체하고 부모 디렉터리를 fsync한다. 생성은 기존 파일을
   덮어쓰지 않는 persist_noclobber를 쓴다.

실패한 검증과 충돌은 원본을 바꾸지 않는다. CLI 동시 쓰기는 잠금으로
직렬화되거나 busy 오류로 끝난다. 프로세스 종료 시 OS가 잠금을 해제하므로
빈 `.ap-lock` 파일이 남아도 stale lock이 아니다. 잠금 파일을 지우면 서로
다른 inode를 잠글 수 있으므로 실행 중 삭제하지 않는다.

이력과 상태는 같은 원자적 파일 안에 있다. JSONL 분리는 두 파일 사이의
부분 커밋 복구 프로토콜이 마련될 때 검토한다. 현재는 파일당 16 MiB 제한이
있고 매번 전체 문서를 읽고 쓴다. 파일은 tempfile의 소유자 전용 권한으로 저장한다.
디렉터리 fsync 실패는 교체 후 발생할 수 있으므로 오류 설명에 따라 재시도 전
revision을 확인해야 한다.

## 검증과 활동

진행/검증 대기/완료로 전환하려면 모든 선행 작업이 완료여야 한다. 완료에는
해당 작업이 요구하는 정확한 종류의 오래되지 않은 근거가 필요하다. 완료 근거는
작업의 완료 조건 전체에 대한 선언이다. 조건별 판정 구조는 아직 없다.
`human` 기록은 사용자 인증 또는 실제 사람이 확인했다는 독립 증명이 아니다.
`automated` 기록 역시 이 도구가 명령을 실행했다는 증명이 아니다.

`invalidate`는 해당 작업과 후속 의존 작업의 근거를 오래됨으로 표시한다.
해당 작업이 진행/완료 상태라면 검증 대기로, 진행한 후속 작업은 막힘으로
돌린다. 코드 revision과 자동 연결한 freshness는 다음 단계다.

`bind`는 연결 식별자만 저장한다. 실행 중인 프로세스를 관측하지 않으며 HUD는
활동을 알 수 없음으로 표시한다. 하네스 설정이나 세션 내용을 수집하지 않는다.

## 아직 보장하지 않는 것

- 임의 편집기는 advisory lock을 따르지 않는다. 바이트 재확인 직후 교체까지의
  짧은 경합은 막지 못한다. 편집기와 CLI를 동시에 쓰지 않아야 한다.
- 직접 편집한 유효한 JSON은 읽을 수 있지만 변경 이유를 자동 재대조하거나
  과거 이력 변조를 탐지하지 않는다. 이력은 감사/인증 로그가 아니다.
- 디스크 손상·전원 장애·비로컬 파일시스템까지 데이터 손실 없음이 검증된 것은
  아니다. 장기 백업/복원과 crash fault injection은 다음 단계다.
- HUD의 마지막 정상 데이터는 메모리 캐시다. 손상된 파일로 재시작하면 오류로
  끝나며 백업에서 자동 복구하지 않는다.
- `q`, Ctrl-C, 반환 오류의 복원 경로와 Ratatui panic hook을 갖는다.
  SIGKILL은 복원 불가능하며 SIGTERM/SIGHUP 처리와 오류 주입 검증은 아직 없다.
