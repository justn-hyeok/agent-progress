# agent-progress 제품 전체 완료 계획

작성일: 2026-09-25. 이 문서는 제품 전체의 실행 순서와 완료 기준이다.
원래 범위는 `product-and-design.md`, 승인된 화면은 `DESIGN.md`를 따른다.
이번 요청은 계획 수립이다. 이 문서를 작성했다고 아래 개발 항목이 완료되거나
구현·외부 배포가 자동으로 시작된 것은 아니다.

## 1. 무엇을 완성이라고 부를 것인가

사용자가 설치한 뒤 Herdr에서 평소처럼 에이전트와 개발하면, 별개 진행 상황 창이
그 세션의 기존 goal/plan을 체크리스트로 가져오고 현재 작업과 체크율을 보여준다.
계획 변경, 세션 종료, 다음 날 새 세션, 연결 오류를 거쳐도 같은 목표와 기록을
이어갈 수 있어야 한다. 사용자가 항목을 다시 등록하거나 원시 로그를 읽으며
상태를 맞출 필요가 없어야 한다.

아래 조건을 모두 충족해야 v1 제품 완료로 판단한다.

- Codex·Claude Code·OpenCode 각각 명시한 지원 버전에서 실제 연결·갱신·복귀
  증거가 있다. 특정 형식의 fixture만 통과한 경우는 실제 연동 완료가 아니다.
- 목표/작업 ID, 완료 조건, 선행 작업, 검증 근거, 막힌 이유, 사용자 행동,
  다음 작업이 세션과 독립적으로 유지된다.
- 항목 이름·순서·분할·병합·취소가 바뀌어도 이력과 체크율의 근거를 추적할 수 있다.
  목표/완료 조건을 축소하는 변경은 사용자 확인 없이 채택하지 않는다.
- 업무 상태, 프로세스 활동, 에이전트 완료 보고, 자동 검증, 사람 확인을 구별한다.
- 중단/손상/동시 실행에서 저장 성공을 보고한 변경이 유실되지 않는다.
  진행 중이던 미확정 변경은 마지막 정상 상태로 복구하고 불확실성을 표시한다.
- 최소 크기는 현재 작업이 들어간 진행 막대, 펼치면 목표/체크리스트/근거/이력.
  정상·빈 상태·막힘·연결 끊김·오류를 키보드로 파악하고 복구할 수 있다.
- 지원 macOS 환경의 새 설치, 업데이트, 이전 데이터 이동, 제거를 검증한다.
  핵심 읽기/기록/표시는 네트워크·서버·goal DB 없이도 작동한다.
- 실제 사용자가 설치→개발→중단→다음 세션 복귀를 수행하고, 현재 위치·막힌 이유·
  다음 행동을 진행 상황 창에서 이해할 수 있음을 확인한다.

## 2. 현재 출발점

| 영역 | 이미 있는 기반 | 제품 완료까지의 차이 |
|---|---|---|
| Codex 입력 | 정확한 pane/PID/rollout 연결, 명시적 대화 계획의 실제 자동 표시 | native goal/plan 실증, 버전 지원표, 설치·연결 점검 |
| 체크리스트 | 원본 상태 반영, 누락 보존, 목표 archive | 문구와 독립적인 ID, 분할/병합/취소, 세션 간 같은 목표 연결 |
| 완료/근거 | 파일 모드 `Task`에는 criteria/dependencies/evidence 존재 | live `Entry/Snapshot`은 더 단순하며 두 경로가 통합되지 않음 |
| 저장 | 원자적 checkpoint, 무결성/경합 검사, legacy 백업 | 사용자 복원 경로, 보존 정책, 정상 마이그레이션, 장애 주입 범위 |
| TUI | 승인된 반응형 막대, 목록/상세/검색/이력 | 여러 목표·프로젝트, 복귀 요약, 근거/사용자 행동의 완전한 흐름 |
| 검증 | 기록된 45개 테스트, PTY, 현재 Codex 대화 계획의 live 증거 | 세 에이전트·깨끗한 설치·실제 복귀 시나리오의 종합 검증 |
| 배포 | 로컬 Cargo 빌드 | 배포 산출물, 설치/업데이트/제거/지원 문서 |

확인 위치: `src/model.rs`, `src/live.rs`, `src/herdr.rs`, `src/runner.rs`,
`src/dashboard.rs`, `src/main.rs`, `tests/`, `scripts/`, `docs/evidence/`.
45개 테스트는 이전 구현 검증 기록이며, 이번 문서 작업에서 재실행한 결과로
표현하지 않는다. 현재는 비 Git 디렉터리이며 Git 초기화·외부 발행을 하지 않았다.

## 3. 실행 순서와 단계별 완료 조건

각 단계의 세 작업은 추적 단위다. 체크는 증거가 확보된 항목만 갱신한다.
기존 구현은 재사용하며 처음부터 다시 만들지 않는다.
테스트는 각 단계에서 함께 작성하고 실행한다. 8단계는 테스트를 처음 하는 때가
아니라 모든 경로를 연결해 확인하는 마지막 단계다.

### 1단계 — 공통 데이터 모델과 체크율 규칙

- [x] AP-01 목표·작업·세션·계획 버전의 식별 및 소유권 계약 확정
- [x] AP-02 파일 모드와 live 모드의 공통 작업/근거 모델 구현
- [x] AP-03 상태 전이·체크율·계획 변경 규칙과 마이그레이션 구현

**핵심 작업:** 제품 전체 목표와 이번 세션의 부분 계획을 구분한다. native goal을
새로 만들 때마다 같은 제품 목표의 체크리스트가 초기화되지 않도록 목표 연결을
명시한다. source는 읽기 전용으로 두고, 작업 ID·근거·이력은 공통 도메인에 둔다.
하네스별 native 데이터/인증 저장소를 공통 DB로 합치지 않는다.
공통 도메인을 진행 창·CLI·MCP의 일관된 읽기 기준으로 삼고, 원본의 보고와
사용자 보정/검증 판정은 출처를 분리해 보존한다. 한쪽 갱신이 다른 쪽 근거를
조용히 덮어쓰지 않도록 충돌 규칙을 확정한다.

작업은 예정/진행/검증 대기/막힘/완료/취소 및 선행 작업·완료 조건·근거를 가진다.
원본의 completed는 우선 에이전트 보고다. 작업이 요구하는 검증 수준을 만족해야
그 정책의 완료로 센다. 검증 요구가 원본에 없으면 이를 임의로 만들어내지 않는다.

**완료 조건:** 같은 입력 사건을 파일/세션 어댑터로 넣었을 때 같은 도메인 상태가
나온다. 항목 0개는 미정, 명시적 취소는 분자/분모 제외, 단순 누락은 자동 취소
아님, 추가 시 분모 증가, 재검증 필요 시 표시/계산 정책이 테스트로 고정된다.

**의존성/산출물:** 첫 단계. 도메인 스키마, 상태 전이표, 호환 fixture 및 변환기.
형식 문서만 작성하거나 live 화면에 파일 모드와 다른 의미가 남으면 완료가 아니다.

### 2단계 — Codex 실제 연동과 Herdr 연결 제품화

- [x] AP-04 Codex 지원 버전·goal/plan 입력 경로·권한 계약 검증
- [x] AP-05 실제 native goal/plan의 생성·변경·완료·재시작 종단 검증
- [x] AP-06 창 열기·중복 연결·연결 끊김·진단 흐름 완성

**핵심 작업:** 공식 인터페이스와 실제 설치본을 확인하고 지원 범위를 기록한다.
현재의 로컬 형식 읽기는 버전이 확인된 어댑터로 격리한다. 대화 계획 fallback도
지원하되 native 입력이 제대로 연결된 것처럼 보고하지 않는다.

`ap open`은 정확한 원본 pane/session에 연결하며 이미 창이 있으면 중복을 방지한다.
프로세스 교체/다른 세션/삭제된 pane을 구별하고 무관한 포커스나 최신 파일을
사용하지 않는다. 진단 명령은 버전·경로·권한·이벤트 수신과 복구 방법을 보여준다.

**완료 조건:** 실제 Codex의 native goal/plan을 변경하면 다른 입력 등록 없이
아래 창의 목표·항목·상태가 반영된다. 두 세션을 동시에 켜도 섞이지 않는다.
실제 새 split, 중복 open, 끊김, 명시적 재연결, 포커스 보존을 검증한다.

**의존성/산출물:** 1단계 계약 이후. 버전 지원표, 진단 결과, 실제 세션 E2E 증거.
실제 입력을 못 받으면 fixture 통과만으로 AP-05를 닫지 않는다.

### 3단계 — 세션 간 이어가기와 계획 변경

- [x] AP-07 프로젝트·제품 목표·작업 ID의 영속 연결 구현
- [x] AP-08 항목 이름/순서/분할/병합/취소와 범위 변경 처리
- [x] AP-09 다음 세션 복귀·요약·여러 목표 선택 구현

**핵심 작업:** 하네스가 제공하는 안정적 ID를 우선 사용한다. 문구만 바뀌었을 때
새 작업으로 복제하지 않는다. ID가 없는 원본의 모호한 대응은 임의 추측으로
완료를 이식하지 않고 확인 가능한 변경으로 남긴다. 목표 자체가 바뀐 경우와
기존 목표를 다음 세션에서 계속하는 경우를 구별한다.
새 세션이 어느 기존 목표에 속하는지 확실히 식별할 수 없을 때만 목표 선택을
한 번 요청한다. 작업 항목을 다시 등록하도록 요구하지 않는다.

복귀 요약에는 마지막 완료, 계획 변경과 이유, 미해결 문제, 필요한 결정,
다음 행동과 원래 근거로 가는 경로를 포함한다. 프로젝트 이동/이름 변경으로
목표가 사라지지 않아야 한다. 발견 사항은 별도 보관하고 자동 범위에 넣지 않는다.

**완료 조건:** 세션 A 종료→세션 B에서 같은 일을 계속할 때 완료 항목·ID·근거·
체크율이 유지된다. 이름/순서 변경으로 항목 수가 불어나지 않고, 합당한 추가/
취소/분할은 이유와 이전 기록을 남긴다. 다른 목표로 옮겼다가 돌아와도 복귀한다.

**의존성/산출물:** 1~2단계. 명시적 연결/변경 계약, resume 시나리오 및 영속 이력.

### 4단계 — 검증 근거, 저장 신뢰성, 복구

- [x] AP-10 완료 조건·검증 근거·freshness를 live 흐름에 연결
- [x] AP-11 백업·복원·동시 실행·스키마 이동·데이터 내보내기 완성
- [x] AP-12 장애 주입·종료 복원·큰 세션의 성능 검증

**핵심 작업:** 에이전트 보고, 지정 검사 결과, 사람 확인을 구분한다. 검사 결과의
대상 revision/시각/출처를 기록하고 코드 변경 시 어떤 근거가 낡았는지 표시한다.
검사 결과의 입력/연결을 제공하되 앱이 에이전트를 지휘하거나 임의 검사를
대신 실행하는 supervisor가 되지 않는다.

복구는 파일을 직접 찾아 고치라는 안내에서 끝나지 않아야 한다. 마지막 정상
기록 선택, 충돌 설명, 백업 미리보기, 안전한 복원, 버전 이동/되돌리기를 제공한다.
실행 중인 중복 창과 동시 writer는 최신 기록을 덮어쓰지 않아야 한다. 토큰·인증
파일·전체 대화를 불필요하게 보관하지 않는지 확인한다.

**완료 조건:** 쓰기 각 지점의 중단·부분 저장·디스크 쓰기 실패·원본 교체·손상·
삭제·중복 실행·soft signal 종료에서 기록과 표시가 일관된다. 강제 종료에서는
마지막 확정 기록을 복구한다. 원래 goal/plan과 사용자 파일은 손상시키지 않는다.

성능 검증에는 10/100/500 MiB 입력과 많은 변경 이력을 포함한다. 기준은 정상
증분 변경 표시 2초 이내, 지연된 외부 조회 중 q 종료 1초 이내를 초기 목표로
삼고 지원 환경에서 측정한다. 달성하지 못하면 병목을 고치거나 지원 한계를
명시하며, 측정 없이 경고만 없애지 않는다.

**의존성/산출물:** 1~3단계. 검증 근거 계약, 복구 도구, 장애/성능 보고서.

### 5단계 — 공통 연결 표면과 나머지 에이전트

- [x] AP-13 공통 어댑터·CLI/MCP·선택적 지침 연결과 진단 완성
- [x] AP-14 Claude Code 실제 연결 및 호환 검증
- [x] AP-15 OpenCode 실제 연결 및 호환 검증

**핵심 작업:** 에이전트별 goal/plan 보유 여부와 이벤트 의미를 먼저 확인한다.
없는 기능을 Codex 형식으로 가정하지 않는다. native goal이 없더라도 계획 기반
흐름을 제공하고, 지원하지 않는 관측/근거는 알 수 없음으로 표시한다.

공통 CLI/MCP는 계획 읽기와 권한 있는 상태·메모·근거 갱신을 제공한다. 일반
사용자는 이를 직접 입력할 필요가 없다. 설치가 지침/훅/설정을 바꿀 경우 변경
미리보기·백업·병합·제거/복구를 제공하며 native 인증 저장소는 변경하지 않는다.

**완료 조건:** 세 에이전트가 동일한 공통 시나리오(연결→계획→갱신→완료→
중단→복귀)를 실제 지원 버전에서 통과한다. 어댑터 실패가 다른 세션/프로젝트를
오염시키지 않는다. CLI/MCP 계약 검사와 제거 후 원상 복구 증거가 있다.

**의존성/산출물:** 1~4단계. 어댑터/스킬/지원표 및 각 실제 환경의 증거.
개발·리뷰는 Codex로 진행한다. 다른 에이전트로 개발을 위임하지 않는다.
제품 입력원으로서의 실제 관찰/검증은 설치·인증·실행 권한이 확보된 환경에서
수행하며, 환경이 없으면 해당 실증을 미완료로 남긴다.

### 6단계 — TUI와 사용 흐름 완성

- [x] AP-16 작은 창 요약→큰 창의 자동 목록·근거·이력 흐름 완성
- [x] AP-17 여러 목표/프로젝트·복귀 요약·사용자 행동 표시 완성
- [x] AP-18 한국어·접근성·상태별 사용성 검증

**핵심 작업:** 현재 승인된 전체 면적 채움 방향을 유지한다. 작은 창은 제품 목표,
현재 계획, 계획상 작업, 실제 원본 위치와 체크율을 보여준다. 커지면 목록/완료
조건/근거/이력이 조작 없이 드러난다. 막힘과 사용자에게 필요한 행동이 정상 진행에
묻히지 않고, 상세에서 원본과 검증 근거로 이동할 수 있어야 한다.

계획 없음, 미정, 오래된 기록, 연결 끊김, 이름 충돌, 권한 부족, 저장 실패,
검증 대기와 완료의 화면/복구 동작을 모두 준비한다. 검색/필터·화면 크기 변경
중 선택과 입력을 보존한다. 색상 외 기호와 숫자, 읽을 수 있는 텍스트 출력을
제공하고 사용하지 않는 source metadata를 작은 창에 노출하지 않는다.

**완료 조건:** 실제 Herdr 작은/큰 pane, 긴 한국어·emoji, 여러 목표, 모든
오류 상태를 별도 조작 없이 파악하고 필요한 복구를 할 수 있다. source pane 입력/포커스를 빼앗지 않는다.
자동 셀/PTY 검증과 사람의 가독성·복귀 이해 확인을 분리해서 남긴다.

**의존성/산출물:** 3~5단계의 상태/복귀 데이터. 화면별 상태/동작 검증 기록.

### 7단계 — 설치·업데이트·제거와 배포 산출물

- [x] AP-19 macOS 지원 OS/아키텍처 표와 재현 가능한 바이너리 빌드
- [x] AP-20 설치·업데이트·되돌리기·제거 및 데이터 이전 검증
- [x] AP-21 사용법·지원 범위·문제 해결·변경 기록·의존성 고지 준비

**핵심 작업:** 사용자가 Rust/Node 개발 환경을 준비하지 않아도 설치 패키지로
실행할 수 있게 한다. Herdr/각 에이전트는 연결 대상이며, 핵심 파일 모드에
필수 서버/계정/goal DB를 추가하지 않는다. 설치/업데이트가 기존 기록과
하네스 설정을 지우지 않게 한다. 제거 시 실행 파일과 사용자 데이터를 구분한다.

**완료 조건:** 명시한 모든 지원 조합의 깨끗한 환경에서 설치→실행→업데이트→
기록 유지→되돌리기→제거를 검증한다. 배포 산출물, checksum, 검증 명령,
사용 문서가 일치하고 개발용 경로·개인 설정 없이 사용할 수 있다.

**의존성/산출물:** 4~6단계. 로컬 배포 패키지와 설치/업데이트 검증 증거.
Git 초기화/commit/push/tag/외부 공개는 현재 계획 요청에 포함하지 않는다.
외부 발행은 준비된 산출물을 대상으로 별도 승인 후 실행한다.

### 8단계 — 제품 전체 종단 검증과 완료 판정

완주된다. 지원 범위의 데이터 유실·잘못된 완료 표시·다른 세션 혼입·사용 흐름을

**의존성/산출물:** 1~7단계 모두. 최종 수용 보고서와 설치 가능한 v1 산출물.
