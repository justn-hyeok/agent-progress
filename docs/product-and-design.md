# agent-progress — 제품 요구사항과 기술 설계 초안

## 문제와 성공 기준

사용자는 긴 에이전트 로그 없이 무엇을 만들고 있는지, 이전에 무엇을 했는지,
현재 위치, 막힌 이유, 필요한 사용자 행동, 이어 할 일을 파악하고 싶다.
에이전트와 사용자가 같은 계획을 읽으며 세션이 바뀌어도 이어갈 수 있어야 한다.
작은 구현 가능 범위가 아니라 매일 사용하는 제품 수준의 범위를 대상으로 한다.

## 제품 경계

로컬 우선, macOS 우선, Rust 단일 바이너리 CLI/TUI를 지향한다.
Ratatui/Crossterm/Notify/Serde는 후보이며 버전과 의존성은 구현 시 검증한다.
핵심 파일 관리와 HUD는 네트워크·서버·DB·Node 런타임 없이 작동해야 한다.
제품이 에이전트를 대신 지휘하거나 코드를 수정하지 않는다.
원격 실행, 조직용 업무 관리, 자동 코드 의미 그래프, 웹 대시보드는 범위 밖이다.

## 목표와 데이터

목표 → 작업 → 완료 조건. 작업에는 고정 ID, 설명, 상태, 선행 작업,
담당 에이전트/세션 연결, 검증 근거, 막힌 이유, 다음 행동이 필요하다.
상태 후보: 예정·진행·검증 대기·막힘·완료·취소.
취소를 완료 수에 포함하지 않는다. 분모 정책은 스키마 확정 시 명시한다.

`ap/2026-09-24/checklist_001.md`처럼 작업별 파일을 사용한다.
날짜는 생성일이며 다음 날이나 다음 세션에서도 같은 파일을 쓴다.
프로젝트 식별과 고정 작업 ID로 경로·번호 충돌을 구분한다.
초안은 하네스 plan이나 대화에서 만들 수 있으나 확정 후 현재 상태 원본은
공통 계획 파일 하나다. plan과 파일을 무조건 양방향 동기화하지 않는다.
goal에는 파일 참조를 넣을 수 있지만 HUD가 goal DB에 의존하지 않아야 한다.

현재 상태 Markdown과 변경 이력 JSONL을 분리하는 안을 검토한다.
명시적 CLI/MCP 변경을 원자적으로 저장하고 충돌을 감지한다.
직접 편집 시에도 형식을 검사하고 재대조한다. 구체적 문법은 아직 미확정이다.

## 사용자 흐름

2026-09-24 사용자 교정: 에이전트에서 평소처럼 개발 → 기존 goal·plan으로
체크리스트 생성 → Herdr 아래쪽 **별도 split 터미널**에 표시 → 계획/완료
변경 자동 반영 → 체크율 확인 → 중단/복귀. 사용자에게 init/add나 작업 ID
복사·별도 상태 등록을 요구하지 않는다. 에이전트 터미널 내부 footer가 아니다.

세션 goal/plan을 읽는 모드는 원본을 수정하지 않는 단방향 projection이다.
파생 체크리스트/진행 이력은 로컬에 보존한다. 위의 공통 Markdown 원본 설계는
선택적 파일 모드에 해당하며, 자동 세션 표시의 선행 절차가 아니다.

HUD는 목표, 현재 계획과 실제 원본 위치, 현재 작업, 완료/남음, 마지막 기록 시각,
에이전트 관측 상태, 막힌 이유, 사용자에게 필요한 행동, 다음 작업을 보여준다.
작은 Pane은 핵심 요약, 큰 화면은 작업 목록과 근거·이력을 자동으로 드러낸다.
상태를 파악하는 데 단축키를 요구하지 않는다. 여러 목표/프로젝트 전환·한국어
줄바꿈·크기 변경을 지원한다.
색상만으로 상태를 구분하지 않으며 자동 스크롤/점멸을 최소화한다.
종료와 오류 시 터미널 상태를 복원한다.

## 에이전트 연결

Codex, Claude Code, OpenCode는 지원 대상이다. 공개 이벤트/API/파일 형식과
권한·버전별 지원 가능성을 먼저 조사해야 하며 아직 연동을 구현한 것은 아니다.
공통 CLI/MCP는 계획 읽기, 항목 시작/완료, 메모/근거 갱신을 제공한다.
에이전트 지침/스킬과 가능한 하네스별 이벤트 어댑터를 제공한다.
전용 연결이 없어도 파일 기반 사용이 가능해야 한다.
연결 점검은 경로·권한·훅·버전·이벤트 수신을 확인한다.
기존 지침/설정을 백업·병합하고 제거/복구 방법을 제공한다.

업무 상태와 에이전트 활동 상태는 별개다. `[>]`만으로 프로세스 실행을
추정하지 않는다. 활동을 관측하지 못하면 알 수 없음으로 표시한다.
프로젝트가 같아도 다른 세션의 계획을 자동으로 섞거나 최신 파일을 임의 선택하지 않는다.

## 계획과 검증의 신뢰성

체크율은 완료 항목/대상 항목이며 제품 완성도나 남은 시간이 아니다.
항목이 없으면 100%가 아니라 미정으로 표시한다.
새 항목으로 체크율이 내려갈 수 있으며 변경 이유를 남긴다.
범위 안의 세분화는 기록하고, 목표/완료 조건 축소는 사용자 확인을 받는다.
새 아이디어는 별도 발견 사항으로 남기고 자동 채택하지 않는다.
완료 보고, 지정 자동 검사 통과, 사람 확인을 구분하고 작업별 필요한 수준을 정한다.
코드 변경으로 근거가 낡으면 재검증 필요를 표현한다.

완료 차단기는 선택적 확장이다. 이전 brgr 실험은 Codex 훅의 조건부 차단과
오류 시 우회 가능성을 보였으므로 절대적 강제로 포장하지 않는다.
Backlog는 필수 의존성이 아니며 필요할 때 입력 어댑터로 고려한다.

## 기록과 복구

복귀 요약: 마지막 완료, 계획 변경과 이유, 미해결 문제, 필요한 결정, 다음 행동.
요약에서 원래 작업과 근거로 이동할 수 있어야 한다.
파일 교체/부분 저장/손상/삭제/동시 수정/중복 실행/연결 단절을 다룬다.
마지막 정상 데이터를 보여줄 경우 오래된 상태임을 명시한다.
설치·업데이트·제거, 설정/스키마 버전 관리, 데이터 내보내기·이동을 포함한다.
비밀번호·토큰·원시 세션 내용을 무분별하게 수집하지 않는다.

## 검증 기준

- 기존 에이전트 goal과 plan에서 체크리스트를 자동 생성하는 것은 필수다.
  목표, 원본 세션, 계획 항목과 상태를 보존하고 별도 사용자 등록을 요구하지
  않는다. 제품 로드맵이 있어도 세션의 실제 목표와 체크리스트를 표시한다.
  제품 수용률과 세션 항목의 완료율은 서로 다른 근거로 구분한다.
- 같은 작업을 여러 세션에서 이어갈 수 있다.
- 로그를 읽지 않고 현재 위치·막힌 이유·다음 행동을 파악할 수 있다.
- 상태 변경과 기록이 충돌/중단 뒤에도 일관되며 데이터 손실이 없다.
- 에이전트별 연동은 실제 지원 환경에서 실행 증거를 갖는다.
- 작은 Pane, 긴 한국어, 리사이즈, 오류 종료를 검증한다.
- 활동 관측·체크율·검증 수준을 혼동하지 않는다.
- 사용자 복귀 시나리오를 실제 작업에서 확인한다.

## 아직 결정할 기술 사항

첫 로컬 구현의 파일 스키마·저장 프로토콜은 `storage-v1.md`, CLI 명령은
README에 기록했다. 직접 편집 재대조·하네스별 지원표·자동 freshness 규칙은
후속 설계에서 확정한다. 구현/미구현 구분은 `current-plan.md`와 `handoff.md`를
따른다. 설계 초안을 이미 구현된 기능으로 보고하지 않는다. 단계를 나누더라도
이 문서의 제품 범위를 임의로 줄이지 않는다.
